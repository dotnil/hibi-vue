# hibi

Проект **hibi** — это приложение для трекинга привычек  с недельной сеткой.

**Demo:** https://hibiflow.ru
**Backend:** https://github.com/dotnil/hibi-hono

---

## Общая архитектура

Проект разделён на два независимых приложения.

- `hibi-hono/`
- `hibi-vue/`

Frontend взаимодействует с backend только через REST API.
Frontend ничего не знает о PostgreSQL.
Backend ничего не знает о Vue.

### Единая модель предметной области

Одной из основных архитектурных идей проекта является единая модель предметной области на frontend и backend.
REST-ресурсы имеют консистентное именование:
сущности API
- **User** — пользователь;
- **Habit** — привычка;
- **Metric** — отметка выполнения привычки за день.

Они определяют как HTTP-клиенты на frontend, так и соответствующие модули backend, содержащие всю логику работы с базой данных.

Благодаря этому структура проекта остаётся предсказуемой: по имени ресурса можно быстро найти связанные HTTP-методы, клиентский API и код, выполняющий SQL-запросы.

Например, ресурс `habits` существует одновременно:
```
backend/
└── habits.js

frontend/
└── api-client/habits.js
```

### Frontend

- реализован на **Vue 3 Composition API** с использованием Single File Components (SFC).
- Логика, не зависящая от Vue, по возможности реализуется через ванильный JavaScript в функциональном стиле, а Vue используется как слой реактивности и композиции интерфейса. 
- Компоненты отвечают только за отображение интерфейса и пользовательские события. Они не выполняют HTTP-запросы и не содержат бизнес-логики.
- Весь обмен данными с сервером сосредоточен в `api-client`, поэтому место использования `fetch` в проекте всегда очевидно.

```
src/
  api-client/   — абстракция над fetch (один модуль на ресурс)
  pages/        — страницы, владеют состоянием
  components/   — презентационные, общаются через emits
  utils/        — чистые функции
```


### Backend

- построен на **Hono** и выполняет единственную задачу — предоставляет REST API для работы с данными. 
- Хранение данных осуществляется в PostgreSQL. 
- Аутентификация пользователей реализована через JWT. Токен хранится в `httpOnly` cookie. Клиент лишь отправляет `credentials: "include"` и не занимается хранением или обновлением токена.
- Пароли пользователей не сохраняются в открытом виде и хранятся только как bcrypt-хэши.
- Каждый модуль backend отвечает за одну предметную область (`users`, `habits`, `metrics`), а SQL находится только внутри этих модулей.

### Минимум зависимостей

Проект сознательно использует минимальный набор инструментов.

Frontend:

- Vue 3
- Vue Router
- Fetch API

Backend:

- Hono
- PostgreSQL
- jose (JWT)
- bcrypt

## Запуск

```shell
npm install
npm run dev
```

### Production

```shell
npm run build
npm run preview   # предпросмотр
nix build         # Nix сборка (./result/)
```

## Переменные окружения

| Переменная  | Dev                     | Prod                      |
|-------------|-------------------------|---------------------------|
| `VITE_BACK` | `http://localhost:3003` | `https://api.hibiflow.ru` |


### Nix flakes для воспроизводимости

`flake.nix` фиксирует версию Node.js и переменные окружения.
Одна команда `nix build` — воспроизводимый production-артефакт без «works on my machine».
